# 城市排水防涝泵站运行与内涝处置管理平台

面向排水泵站台账、泵组运行、排水管网与检查井养护、水位雨量监测、内涝点处置、闸门调度与抢险队出动的一体化城市排水防涝运行管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`；泵组运行有专门的开机/停机规矩，收在
  `frontend/src/api/pump-run-service.ts`。
- 字段、状态、动作、流转目标与状态机（`transitions` / `finalStatuses`）集中在
  `frontend/src/data/modules.ts`；示例数据在 `frontend/src/data/seed.ts`。
- 状态流转只允许在服务层改，页面组件不做业务判断；动作按钮按当前状态只露出"下一格"。
- 想回到初始数据：清掉浏览器里 `drainage-pump:entries:v2` 这一项，或调用 `resetModule(模块)`。

## 泵组开机/停机规矩

泵组运行模块（`pumprun`）按以下规矩运行，规则都在 `pump-run-service.ts` 里，页面只做展示：

1. **状态只能顺走**：待开机 → 运行中 →（已停机｜故障停机）。动作只在当前状态的"下一格"
   出现，服务层对跳级（如待开机直接停机、终态再操作）一律打回。
2. **同一台泵不重开**：同一「所属泵站 + 泵组编号」已有运行中的记录时，第二条记录的开机确认
   被挡住，要等这台泵停机后才能再开。
3. **超额定电流挡住确认**：额定电流以内置泵组台账 `PUMP_UNITS` 为准；运行电流超过额定值的
   记录整行标红、写明超出多少安与百分比，并挡住开机确认，必须改记电流到额定值以内才能开机。
4. **运行编号、所属泵站、泵组编号三格联合查询**：三格一起核对，查不到时逐格说明是哪一格没
   对上（编号错、泵站格错、泵组挂在别站名下等）。
5. **停机自动算时长**：按开机时间与停机时间的实际差值累计，跨零点（如 22:10 → 次日 02:05）
   不需要特殊处理，直接得到 3小时55分钟。
6. **停机结论落到检修待修清单**：登记停机或上报故障后，`pumpmaint` 自动生成一条「待开工」
   检修待办（故障为「故障检修」并标异常），结论随运行单带过去；同一条运行单只落一次待办。

规矩的自动化验证：

```bash
cd frontend
npm run smoke:pumprun   # 25 条断言：跳级、重开、超标、联合查询、跨零点时长、待办联动
```
